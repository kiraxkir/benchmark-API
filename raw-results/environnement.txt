Configuration Laravel
- php-fpm pm=static, pm.max_children=10, pm.max_requests=0, log d'accès php-fpm supprimé ;
  nginx access_log off ; OPcache activé (validate_timestamps=0), JIT non activé (défaut).
- config:cache au démarrage du conteneur (secrets non figés dans l'image), route:cache au build,
  autoloader Composer --classmap-authoritative, APP_ENV=production, APP_DEBUG=false.
- PDO::ATTR_PERSISTENT=true (1 connexion par worker -> 10 connexions vérifiées dans processlist),
  ATTR_EMULATE_PREPARES=true (CLAUDE.md §5.6.12). À chaque requête, Laravel exécute « use `mri` » et
  « SET NAMES utf8mb4 COLLATE utf8mb4_0900_ai_ci, SESSION sql_mode=… » (comportement par défaut
  du connecteur MySQL de Laravel, conservé).
- Middlewares globaux TrimStrings et ConvertEmptyStringsToNull retirés (validation manuelle
  identique aux 3 autres versions) ; middleware RejectTrailingSlash ajouté (Laravel ignore la
  barre oblique finale, les autres non).
- Limites : laravel-fpm cpus=2 / 1g ; laravel-nginx cpus=0.5 / 128m en plus (décision du groupe,
  CLAUDE.md §5.6.11 ; à signaler dans les Limites du rapport).

Configuration FastAPI
- uvicorn --workers 2 --no-access-log --log-level warning (uvloop + httptools via uvicorn[standard]).
- Pool aiomysql par worker : minsize=1, maxsize=5, autocommit=True -> 10 connexions vérifiées.
- Corps JSON validé à la main (pas de modèle Pydantic), docs/OpenAPI désactivés,
  redirect_slashes=False, gestionnaires d'erreurs -> {"error": ...}.

Configuration Spring Boot
- java -Xmx512m -jar (JVM sans autre réglage), Tomcat par défaut (200 threads max),
  logging.level.root=WARN (PageNotFound en ERROR : pas de ligne par 404), pas d'access log,
  pas de Whitelabel, pas de ressources statiques, ProblemDetails désactivés.
- HikariCP maximum-pool-size=10 (10 connexions vérifiées), auto-commit.
- Connector/J : sslMode=DISABLED (comme les 3 autres pilotes, sans TLS),
  allowPublicKeyRetrieval=true.
- Corps lu en octets et analysé avec Jackson 3 (FAIL_ON_TRAILING_TOKENS), réponse sérialisée
  avec Content-Type fixe application/json (pas de négociation de contenu, Accept ignoré).

Configuration Gin
- gin.SetMode(ReleaseMode), gin.New() + gin.CustomRecovery (= Recovery avec réponse 500 au format
  du contrat), pas de Logger ; RedirectTrailingSlash/RedirectFixedPath désactivés.
- SetMaxOpenConns(10), SetMaxIdleConns(10) (10 connexions vérifiées), collation utf8mb4_0900_ai_ci.
- interpolateParams=true (CLAUDE.md §5.6.12).
- Binaire statique (CGO_ENABLED=0). Go >= 1.25 règle GOMAXPROCS sur la limite CPU du cgroup (2).

Envoi des requêtes SQL (mesuré avec SHOW GLOBAL STATUS, 20 GET /api/posts par API)
- Avant harmonisation : Laravel (préparées natives) USE + SET + PREPARE/EXECUTE/CLOSE ;
  Gin PREPARE/EXECUTE/CLOSE ; FastAPI et Spring : 1 requête interpolée côté client.
- Après (option 2 retenue par le groupe) : 1 requête SQL interpolée côté client dans les 4 API,
  0 PREPARE ; Laravel exécute en plus USE + SET à chaque requête HTTP (à signaler en Limites).

Outillage de mesure (phase 4)
- k6 v2.4.0 lancé avec --quiet --no-usage-report ; scénario load-tests/mixed.js (constant-vus, sans
  pause), résumé via handleSummary. Structure du JSON v2 vérifiée avant d'écrire le parseur.
- docker stats lu en flux continu (rafraîchi ~2 fois/s, valeurs mises à jour ~1 fois/s) dans un thread,
  au lieu d'appels --no-stream répétés (~1,5 s chacun). CPU en % d'un cœur (2 cœurs = 200 %),
  RAM en Mio ; Laravel = php-fpm + nginx sommés.
- startup_time.py : docker compose stop puis up -d --no-build (conteneur existant relancé, pas recréé),
  chronométré jusqu'au premier 200 (sondage 50 ms) ; inclut le coût de la commande docker compose.
  Cache disque de l'hôte chaud.
- Durabilité MySQL : la configuration par défaut de mysql:8.4 (innodb_flush_log_at_trx_commit=1,
  sync_binlog=1, binlog activé, doublewrite ON, O_DIRECT) coûtait ~9 ms par INSERT en autocommit
  avec un seul client (200 INSERT, 3 séries : 9,0 / 9,4 / 8,7 ms) sur le disque WSL2.
  -> Décision du groupe (option b, CLAUDE.md §6) : --innodb-flush-log-at-trx-commit=2 --skip-log-bin.
     Mesuré ensuite : coût d'un INSERT non distinguable d'un SELECT 1 (< 0,1 ms d'écart).
- Essais à blanc (1 essai de 5 s par charge, conservés dans raw-results/essai-a-blanc/) :
  1-durabilite-complete/ (avant option b) et 2-option-b/ (après). Ne font pas partie de la campagne.

Remarque authentification MySQL
- root utilise caching_sha2_password. Sans TLS, PyMySQL (sans le paquet cryptography) ne sait
  pas faire l'échange RSA complet ; il réussit grâce au cache du serveur, rempli par le
  healthcheck (mysqladmin ping toutes les 5 s) avant que les API démarrent (service_healthy).
  Vérifié : redémarrage de MySQL puis de FastAPI seul -> 200.

Écarts par rapport à CLAUDE.md (et pourquoi)
- MySQL : service compose « mysql », conteneur « mysql-dev », port hôte 3307. Les API joignent
  MySQL par le réseau Docker (mysql:3306).
- MySQL lancé avec --default-time-zone=+00:00 et utf8mb4 explicites pour que le suffixe « Z »
  des dates soit exact.
- reset.sql remet aussi les AUTO_INCREMENT à leur valeur initiale (identifiants reproductibles
  d'un essai à l'autre).
- schema.sql : InnoDB crée automatiquement un index sur comments.user_id (exigé par la FK).
